Xboost privacy policy

Effective September 13, 2026. This policy describes the Xboost Chrome extension.

Local processing and storage

The profile editor stores custom profile names, descriptions, intended X handles and authoritative AI context locally. Custom context is sent with generation requests when AI is enabled. Queued posts retain a snapshot of their selected account and custom context even if the profile is later edited.

Xboost reads rendered X/Twitter posts to score and highlight conversations. Profile settings, keywords, filters, appearance theme, About-button visibility, Codex server address, capability token and discovery state are stored in Chrome extension-local storage, not Chrome Sync. Source posts, generated drafts, profile-context revisions, error details, reply history and deduplication records are stored in extension-owned IndexedDB on the same local browser profile. Dismiss hides a draft; it does not erase its stored record. Upgrades migrate the earlier draft array to IndexedDB and retain the legacy copy until transfer validation succeeds. Temporary reply handoffs are held in background memory and expire after 30 minutes.

Optional AI drafting

User-driven discovery stores the selected profile, session target, profile/context snapshot and revision identifier, search variants, owned search-tab binding, visited source IDs, source timestamps, rejection counts, progress and cooldowns locally. Starting discovery enables drafting and sends eligible loaded posts and the selected context to your configured Codex server and OpenAI. Eligible highlighted posts already rendered while you browse or scroll other open X pages can join the selected profile's running session. Xboost locally rechecks rendered posts when draft capacity opens; this does not refresh, scroll or navigate those pages. Search variants use saved keywords and literal topics from product context. Clicking Open next deep search sends up to three adjacent terms joined with OR, an optional intent, reply exclusion and Latest/Top selection to X; clicking the simple fallback sends one term without operators. Activating the owned discovery tab changes Xboost's locally stored active profile to the session profile; it does not change the signed-in X account. Do not put confidential terms in targeting/context that you do not want used in searches. The extension does not navigate unrelated tabs or open, refresh or scroll discovery searches unattended. Pause, Stop and closing the last AI panel halt new session work and request cancellation; restart requires explicit resume. Historical drafts and records are preserved.

Follow-back on X opens X Notifications directly; it no longer imports follower or like records. Any records imported by an earlier version remain in local storage until extension data is removed and are not sent to AI. Reply confirmations, edited sent text and timestamps are stored locally. Cross-profile assessments are no longer available and pending assessments will not run; old results remain stored locally but are not displayed. Subsequent drafts include previously confirmed replies on the source post to help avoid duplication.

Manually selecting a post saves its text, author and URL locally even while AI is disabled. Keyword and hashtag suggestions are extracted locally without calling AI. Only terms you choose or enter are added to the selected profile. Selected posts are sent for drafting only when you enable AI.

AI drafting is off until you enable it. While enabled, qualifying posts from open X tabs can be queued automatically. Post text, author handles, post URLs and the selected authoritative profile context are sent to the Codex App Server you configure and processed by OpenAI through that server. Created profiles, the X handle parsed from an entered @name or profile URL, targeting and context are stored locally. Deleting a profile removes its settings but deliberately preserves historical drafts and reply records. Source posts may contain personal information. Do not enable AI for content you are not authorized to share.

A Chrome session header rule holds the token, limited to requests from this extension to the exact WebSocket endpoint. The capability token is sent only to your configured server for authentication. Server status and account sign-in operations also communicate with that server. Codex manages its OpenAI account credentials on the server; Xboost does not read ChatGPT browser cookies. The extension does not operate a developer-hosted collection backend or include analytics, advertising trackers or telemetry.

X navigation and assisted replies

Search buttons send profile keyword queries to X through normal browser navigation. Opening a source post sends its URL to X. On request, Xboost checks the visible active account and inserts a draft into X's composer. X can process text entered into its site even before you submit it. Xboost never automatically clicks Send, Like or Follow, and does not switch X accounts. Copy buttons put draft text on your system clipboard.

Recipients and security

Your configured server operator, OpenAI and X handle data according to their own settings and policies. Xboost does not control their retention, training settings or deletion. If you operate the Codex server yourself, review its configuration and logs. Both ws:// and wss:// are supported. Plain ws:// is unencrypted and can expose the capability token and messages to network observers. Prefer localhost with SSH port forwarding, or encrypted wss:// for remote connections. The capability token is stored locally without additional extension-level encryption; protect your Chrome profile and server.

Controls and deletion

Disable AI to stop new collection and request cancellation of active drafting. Closing the last AI panel pauses drafting. Cancellation cannot be confirmed if the server is disconnected. Queued and completed records remain stored until removed. Uninstall Xboost to remove its extension-local data from Chrome; any separate backups or server/provider records must be managed separately. Clear your clipboard separately. Revoking the server capability token prevents future use of that token. The extension is disabled in private browsing.

Contact and changes

Use the support contact published on Xboost's Chrome Web Store listing for privacy questions. Policy changes will be included with extension updates and reflected on that listing.
